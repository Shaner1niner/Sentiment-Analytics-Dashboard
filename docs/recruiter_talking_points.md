# Recruiter Talking Points

## One-sentence summary

Built a sentiment analytics dashboard portfolio that combines social sentiment, engagement behavior, market context, SQL reporting logic, and Tableau-style visual storytelling into a public, recruiter-friendly analytics showcase.

## Professional positioning

This project is best described as a financial analytics and reporting system, not as a trading signal product.

Preferred language:

> I built a sentiment intelligence dashboard that studies market narratives, public attention, and engagement behavior across financial assets using Python, SQL, PostgreSQL-style data modeling, and Tableau-oriented visualization design.

Avoid positioning it as:

- a trading bot
- a buy/sell signal engine
- investment advice
- a guaranteed prediction system

## Skills demonstrated

- Python-based analytics workflow design
- SQL reporting and data modeling
- Dashboard planning and Tableau implementation logic
- Sentiment and engagement analysis
- Data storytelling for non-technical audiences
- Public-safe documentation and communication
- Separation of showcase assets from private production infrastructure

## Why this matters for accounting and finance roles

The project demonstrates the ability to:

- structure messy data into decision-ready reporting layers
- explain analytical outputs clearly
- think in terms of controls, governance, and repeatable workflows
- design dashboards that communicate business context
- combine accounting discipline with modern analytics tooling

## Suggested resume bullet

Built a sentiment analytics dashboard portfolio using Python, SQL, PostgreSQL-style reporting structures, and Tableau design logic to analyze market narratives, engagement behavior, and sentiment trends across financial assets.

## More technical resume bullet

Developed a multi-source sentiment analytics framework and public dashboard showcase with sanitized sample data, SQL reporting examples, data dictionary documentation, and Tableau calculation notes while keeping production ingestion, weighting, orchestration, and live database infrastructure private.

## Interview explanation

The public repository is intentionally curated. It demonstrates the architecture, dashboard layer, sample reporting structures, and analytical communication style without exposing proprietary ingestion pipelines, weighting methodology, credentials, or production infrastructure.
