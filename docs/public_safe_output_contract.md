# Public-Safe Output Contract

## Purpose

This document defines language standards for a public analytics dashboard. The goal is to keep dashboard copy educational, descriptive, and reviewable.

## Core rules

Public dashboard outputs should:

- describe conditions rather than prescribe actions
- explain sentiment and attention context
- avoid certainty claims
- avoid personalized guidance
- separate attention from validation
- preserve room for human review

## Acceptable output categories

### Sentiment context

Describe public tone as positive, negative, neutral, mixed, improving, or deteriorating.

### Attention context

Describe discussion levels as low, normal, elevated, concentrated, broad, or noisy.

### Narrative context

Describe whether the public discussion backdrop appears constructive, stressed, mixed, crowded, or unresolved.

### Market context

Describe price and volume as supporting context rather than as instructions.

## Preferred wording

Use terms such as:

- public tone
- attention level
- engagement pattern
- narrative pressure
- market context
- participation breadth
- sentiment backdrop
- dashboard context
- mixed signal
- elevated discussion

Avoid terms such as:

- guaranteed
- certain
- risk-free
- prediction certainty
- personalized recommendation language

## Output structure

A safe dashboard note should identify the asset or topic, summarize sentiment, summarize attention, describe the narrative backdrop, and state that the output is analytical context.

## Human review rule

Automated summaries should be treated as draft analytical copy. Human review should remain part of any workflow that publishes commentary externally.
